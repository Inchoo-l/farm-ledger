# 復元手順書（自動バックアップから元に戻す）

バックアップが入っているのは、Google ドライブの **「バックアップ」フォルダ** です。
中には、いつも **フル1個＋次のフルまでの増分** が入っています。

```
バックアップ
├─ フル_1108.json     ← 日曜に取った、データ全部
├─ 増分_1109.json     ← 月曜：日曜からの変更だけ
├─ 増分_1110.json     ← 火曜：月曜からの変更だけ
└─ 増分_1111.json     ← 水曜：火曜からの変更だけ
```

復元は、**フル → 増分を日付の順に、1つずつ当てはめる**ことで、元の状態に戻します。
（日付の順は、ファイル名ではなく、ファイルの中の記録で決めるので、年をまたいでも大丈夫です。）

> パスワードで暗号化している場合、バックアップのファイルも**暗号化されたまま**です。復元のときに、共有ファイルと同じパスワードを入力します。

---

## 方法A：アプリの画面から復元する（おすすめ）

1. Google ドライブで **「バックアップ」フォルダ** を開きます。
2. 中の**ファイルをすべて**選んで、ダウンロードします（複数だと zip になります。zip は、ダブルクリックなどで展開して、`.json` のファイルを取り出します）。
3. アプリを開き、**「全体」→「💾 バックアップ」** タブへ進みます。
4. **「☁ 自動バックアップから復元（フル＋増分）」** の **「ファイルを複数選ぶ」** を押します。
5. ダウンロードした `.json` を**すべて**選びます（Ctrl キーを押しながらクリック、または Ctrl+A）。
6. パスワードを聞かれたら、共有ファイルと同じパスワードを入力します。
7. 「フルバックアップ（◯月◯日）＋増分◯件 を当てはめて、◯月◯日 の状態に戻します」と確認が出ます。内容を見て **OK** を押します。
8. 「復元しました」と出れば完了です。

- **間違えたとき**：復元の直後なら、画面上の「↩ 元に戻す」で、復元する前の状態に戻せます。
- **「増分が足りません」と出たとき**：増分が1つ抜けています。メッセージに、足りない増分の日付が書いてあります。
  ゴミ箱に入っていないか確認するか（下の「ゴミ箱から戻す」）、**フルだけで復元**してください（方法B）。何も変更せずに止まるので、安全です。
- 古いフルと、新しいフルが混ざっていても、**いちばん新しいフルとそれにつながる増分**を自動で選びます。

---

## 方法B：フルだけで復元する（その週の日曜の状態に戻す）

増分が足りないときや、「日曜の状態に戻したい」ときに使います。

1. ドライブの「バックアップ」フォルダから、**`フル_◯◯◯◯.json` だけ**をダウンロードします。
2. アプリの **「💾 バックアップ」→「バックアップと復元」→「復元する」** を押し、そのファイルを選びます。
3. 暗号化されていれば、パスワードを入力します。確認が出たら **OK** を押します。

> 増分のファイル（`増分_◯◯◯◯.json`）を、この「復元する」に選ぶと、案内が出て止まります（増分だけでは復元できないためです）。

---

## 方法C：コマンドで復元ファイルを作る

アプリが開けないときや、中身を確かめたいときに使います（Node.js が入っているパソコンで）。

```powershell
cd G:\ProgramingDesctop\agriWebApps\backup-worker
node tools/restore.mjs C:\Users\あなた\Downloads\バックアップ restored.json
```

- パスワードを聞かれたら入力します（画面には出ません）。
- `restored.json` ができます。アプリの **「復元する」** で読み込んでください。

---

## ゴミ箱から戻す

古いバックアップ（前の週のフルや増分）は、新しいフルが成功したときに、**ゴミ箱へ移る**だけで、**30日間は戻せます**。

1. Google ドライブの左のメニュー **「ゴミ箱」** を開きます。
2. `フル_◯◯◯◯.json`／`増分_◯◯◯◯.json` を右クリック →「復元」します。

---

## 復元したあとの注意

- アプリで **共有ファイル（Google ドライブ）に接続している場合**、復元したデータが共有ファイルにも書き込まれます。ほかの端末にも、数秒〜数十秒で反映されます。
- 復元で戻るのは、**バックアップを取った時点まで**です（毎日深夜1:00の状態）。それ以降にした入力は戻りません。

---

## 仕組み（知りたい人向け）

- **フル**：データまるごと（`_backup` という管理用の項目が付いています。復元のときは取り除きます）。
- **増分**：前回のバックアップからの
  「追加・変更された記録」「削除された記録の番号」「並び順」「設定などの変更」だけ。
  各増分には、**自分の時刻（stamp）と、土台にした1つ前の時刻（base）**が入っていて、`フル → 増分 → 増分…` の鎖が**つながっているか**を、復元のたびに確かめます。
- 鎖が切れていたら、**間違った状態に戻さず**、どこが足りないかを伝えて止まります。
- 毎日の自動バックアップの側も、実行のたびに鎖を確かめ、おかしければ増分ではなく**フルを取り直します**（自己修復）。

### テスト（開発者向け）

```powershell
cd G:\ProgramingDesctop\agriWebApps\backup-worker
npm test
```

乱数で作ったデータに、追加・変更・削除・並べ替えを300日ぶん重ね、毎日、「フル＋増分の復元」が元のデータと**完全に一致する**ことを確かめています。
暗号化あり・なし、同じ日の再実行、失敗したときに古いものが残ること、鎖が切れたときの自己修復なども、テストに入っています。

# 自動バックアップ 設定手順書（はじめての人向け）

毎日、日本時間の深夜1:00に、帳簿のデータを Google ドライブの「バックアップ」フォルダへ自動で保存します。
**この手順書のとおりに設定が終わるまでは、何も動きません**（まだ公開もしていません）。

- 日曜日：**フルバックアップ**（データ全部）
- ほかの曜日：**増分バックアップ**（前回からの追加・変更・削除だけ）
- フォルダには、いつも「フル1個＋次のフルまでの増分」だけが入ります（古いものは、新しいフルが成功してからゴミ箱へ）
- ファイル名の例：`フル_1109.json`、`増分_1110.json`
- 失敗したら、スマホに通知（ntfy）が届きます
- 費用：0円（Cloudflare・Google・ntfy の無料の範囲）

> 所要時間の目安：30〜40分。わからなくなったら、その画面のスクショを私に見せてください。

---

## 0. 全体の流れ

| 番号 | やること | どこで |
|---|---|---|
| 1 | Google の OAuth を「本番環境」にする | Google Cloud |
| 2 | リフレッシュトークンを取る | Google OAuth Playground |
| 3 | 通知（ntfy）を用意する | スマホ |
| 4 | 共有ファイルの「鍵」を表示する | アプリ |
| 5 | 秘密情報を Cloudflare に登録する | パソコン（PowerShell） |
| 6 | 手元で動作確認する（本番前のお試し） | パソコン（PowerShell） |
| 7 | 公開する（デプロイ） | パソコン（PowerShell） |

用意するもの：Google アカウント、Cloudflare のログイン済みの環境（今までデプロイに使ったもの）、スマホ。

---

## 1. Google の OAuth を「本番環境」にする

今の設定は「テスト中」のはずです。**テスト中のままだと、7日たつとログインが切れて、バックアップが止まります。**
「本番環境」にすれば、切れません。個人用のアプリでも大丈夫で、審査もありません
（使っている権限 `drive.file` は、Google が「審査不要」と定めている種類です）。

1. <https://console.cloud.google.com/> を開き、いつものプロジェクトを選びます。
2. 左のメニューから **「Google Auth Platform」** を開きます（見つからないときは、上の検索欄に「Google Auth Platform」と入れます）。
3. **「ブランディング」** を開き、次の3つが入っているか確認します。入っていなければ入力して「保存」します。
   - アプリ名（例：帳簿アプリ）
   - ユーザーサポートメール（自分のGmail）
   - デベロッパーの連絡先メール（自分のGmail）
   - ※**ロゴは入れないでください**（ロゴを入れると、Google の審査が必要になることがあります）。
   - ※アプリのホームページなどのURL欄は、空のままで大丈夫です。
4. **「対象」** を開きます。「公開ステータス」が **「テスト」** になっています。
5. **「アプリを公開」** のボタンを押します。確認の画面が出たら **「確認」** を押します。
6. 公開ステータスが **「本番環境」** に変われば完了です。

> 前回「アプリを公開」が灰色で押せなかったのは、手順3の入力が足りなかったからだと思われます。
> もし今回も押せない、または「確認が必要です」と出たら、その画面をスクショして私に見せてください。

## 2. リフレッシュトークンを取る

Worker があなたの代わりにドライブへアクセスするための「許可証」を取ります。
**アプリで使っているクライアントIDと、必ず同じクライアントIDを使います**
（違うと、アプリが作った共有ファイルが、Worker から見えません）。

### 2-1. クライアントIDとシークレットを確認する

1. Google Cloud の **「Google Auth Platform」→「クライアント」** を開きます。
2. アプリで使っている **ウェブ アプリケーション** のクライアントをクリックします。
3. **クライアントID**（`….apps.googleusercontent.com` で終わる文字列）を、メモ帳にコピーしておきます。
4. **クライアント シークレット** を確認します。
   - 画面に見えていれば、メモ帳にコピーします。
   - 見えない（一部しか表示されない）ときは、**「シークレットを追加」** のようなボタンで新しく作り、表示された全体をコピーします（古いシークレットは消さなくて大丈夫です）。
   - ※シークレットは**他人に見せない**でください。

### 2-2. 「承認済みのリダイレクト URI」を追加する

1. 同じクライアントの画面で、**「承認済みのリダイレクト URI」** に次を追加します。

   ```
   https://developers.google.com/oauthplayground
   ```

2. 「保存」を押します（反映に数分かかることがあります）。

### 2-3. OAuth Playground でトークンを取る

1. <https://developers.google.com/oauthplayground/> を開きます。
2. 右上の **歯車のアイコン**（OAuth 2.0 configuration）を押します。
   - **「Use your own OAuth credentials」** にチェックを入れます。
   - **OAuth Client ID** と **OAuth Client secret** に、2-1 でコピーした値を貼ります。
   - 「Access type」が **Offline** になっていることを確認します（初期値は Offline です）。
3. 左の **「Step 1 Select & authorize APIs」** で、一番下の入力欄 **「Input your own scopes」** に、次を貼って **「Authorize APIs」** を押します。

   ```
   https://www.googleapis.com/auth/drive.file
   ```

4. Google のアカウントを選び、確認画面で **「許可」** を押します。
5. **「Step 2 Exchange authorization code for tokens」** の **「Exchange authorization code for tokens」** ボタンを押します。
6. **Refresh token** の欄に、`1//` で始まる長い文字列が出ます。これを**全部**コピーして、メモ帳に貼ります。

> よくある失敗
> - `redirect_uri_mismatch`：2-2 の URI が正しく保存されていません（数分待って、もう一度）。
> - Refresh token が出ない：歯車の「Access type」が Offline か確認して、手順3からやり直します。

## 3. 通知（ntfy）を用意する

失敗したときと、毎週日曜のフルバックアップ完了のときに、スマホに通知が届きます
（**日曜の通知が来なくなったら、止まっているサインです**）。

1. スマホに **ntfy** アプリを入れます（iPhone：App Store、Android：Google Play。無料）。
2. **ほかの人に推測されない、長いトピック名**を決めます。例：`tanbo-backup-k7q2m9x4c1`
   （英小文字と数字だけで、10文字以上のランダムな部分を付けてください。トピック名を知っている人は、誰でも通知を見られます）
3. ntfy アプリで「＋」→ そのトピック名を入力して購読します。
4. 試しに通知を送ってみます。PowerShell で（トピック名は自分のものに）：

   ```powershell
   Invoke-RestMethod -Method Post -Uri https://ntfy.sh/あなたのトピック名 -Body "テスト通知"
   ```

   スマホに「テスト通知」が届けばOKです。

## 4. 共有ファイルの「鍵」を表示する

共有ファイルをパスワードで暗号化しているので、Worker が中身を読めるように、**パスワードから作った「鍵」**を渡します。
（パスワードそのものは渡しません。バックアップのファイルも、同じ鍵で**暗号化されたまま**ドライブに保存されます。）

1. アプリを開き、Google ドライブに接続した状態にします。
2. 「全体」→「💾 バックアップ」タブの上の **共有ファイル** のカードで、**「🔑 自動バックアップ用の鍵を表示」** を押します。
3. 共有ファイルのパスワードを入力します。
4. 出てきた文字列（`{"v":1,"salt":…}` の形）を、**「コピーする」** でコピーして、メモ帳に貼ります。

> **この鍵は、パスワードと同じくらい大切です。** 他人に見せたり、メールやチャットに貼ったりしないでください。
> **共有ファイルのパスワードを変えたときは、鍵も変わります。** その場合は、もう一度ここで鍵を表示して、手順5の `DATA_KEY` を登録し直してください
> （変えたまま放っておくと、通知で「パスワードが変わっています」と知らせます）。

## 5. 秘密情報を Cloudflare に登録する

PowerShell を開いて、次のとおり進めます。

```powershell
cd G:\ProgramingDesctop\agriWebApps\backup-worker
```

### いちばん簡単な方法（質問に答えるだけ）

```powershell
.\秘密情報を登録.ps1
```

聞かれる順番に、メモ帳の値を貼り付けて Enter を押します。

| 聞かれるもの | 貼るもの |
|---|---|
| GOOGLE_CLIENT_ID | 2-1 のクライアントID |
| GOOGLE_CLIENT_SECRET | 2-1 のクライアント シークレット |
| GOOGLE_REFRESH_TOKEN | 2-3 の Refresh token |
| DATA_KEY | 手順4の鍵（`{"v":1,…}` を全部） |
| NTFY_TOPIC | 手順3で決めたトピック名 |

途中で「Worker がありません。新しく作りますか？」と聞かれたら、**Y** と答えます。

> うまくいかないときは、1つずつ登録することもできます：
> `npx wrangler secret put GOOGLE_CLIENT_ID` を実行し、値を貼って Enter（ほかの4つも同じ）。

登録した秘密情報は、あとから**中身を見ることはできません**（Cloudflare の仕組みです）。メモ帳のコピーは、安全な場所に残しておいてください。

## 6. 手元で動作確認する（本番前のお試し）

本番の前に、自分のパソコンで試します。**本物のドライブにアクセスします**（「バックアップ」フォルダができます）。

1. `.dev.vars.example` を `.dev.vars` という名前でコピーし、中身を書き換えます（手順5と同じ5つの値）。

   ```powershell
   Copy-Item .dev.vars.example .dev.vars
   notepad .dev.vars
   ```

   ※**`.dev.vars` は他人に見せない**でください。確認が終わったら、手順6-4で削除します。

2. お試し用のサーバーを起動します（このウィンドウは開いたままにします）。

   ```powershell
   npx wrangler dev --test-scheduled
   ```

   「Ready on http://localhost:8787」と出れば起動しています。

3. **別の PowerShell ウィンドウ**を開いて、順番に試します。

   **(a) 計画だけ確認（何も保存しません）**

   ```powershell
   Invoke-WebRequest "http://localhost:8787/cdn-cgi/handler/scheduled?cron=dry-run" -UseBasicParsing
   ```

   起動したウィンドウに、次のようなログが出ます。
   - `共有ファイルを読みました（暗号化=true、…）` → **共有ファイルが見えて、鍵も合っています**
   - `計画：フル …` → 初回はフルになります

   エラーが出たら、「9. うまくいかないとき」を見てください。

   **(b) 実際にフルを1つ保存**

   ```powershell
   Invoke-WebRequest "http://localhost:8787/cdn-cgi/handler/scheduled?cron=force-full" -UseBasicParsing
   ```

   Google ドライブ（マイドライブ直下）に **「バックアップ」** フォルダができ、中に `フル_月日.json` が1つ入っていれば成功です。

   **(c) 増分も試す**（共有ファイルをアプリで少し変更してから）

   ```powershell
   Invoke-WebRequest "http://localhost:8787/cdn-cgi/handler/scheduled?cron=force-incr" -UseBasicParsing
   ```

   `増分_月日.json` が増えます（同じ日に何度やっても、ファイルは増えず上書きされます）。

4. 確認が終わったら、起動したウィンドウで `Ctrl + C` を押して止め、`.dev.vars` を削除します。

   ```powershell
   Remove-Item .dev.vars
   ```

> 手元で試した `フル_…` と `増分_…` は、そのまま残して大丈夫です（本番の最初のフルで整理されます）。

## 7. 公開する（デプロイ）

手順6がうまくいったら、公開します。

```powershell
npx wrangler deploy
```

「Deployed tanbo-backup triggers」と、`schedule: 0 16 * * *` が表示されれば完了です。

- `0 16 * * *` ＝ 毎日 UTC の16:00 ＝ **日本時間の翌日 1:00** です。
- 日曜かどうかは、コードの中で**日本時間に直して**判定しています（cron の曜日は使っていません）。

### 公開したあとの確認

- 翌朝、ドライブの「バックアップ」フォルダに、前日の日付のファイルが入っているか見ます。
- **日曜の朝に、ntfy へ「帳簿のフルバックアップ完了」が届けば、正常に動いています。**
- 届かない日曜があったら、止まっている可能性があります。「9. うまくいかないとき」を見てください。

## 8. 設定を変えたいとき

`wrangler.jsonc` の `vars` の部分を書き換えて、`npx wrangler deploy` をやり直します。

| 名前 | 意味 | 初期値 |
|---|---|---|
| `FULL_DAY` | フルを取る曜日（0=日曜、1=月曜 … 6=土曜。日本時間） | `0` |
| `NOTIFY_ON_SUCCESS` | 成功の通知。`full`＝フルの日だけ／`all`＝毎日／`none`＝出さない（失敗の通知は常に出ます） | `full` |
| `DATA_FILE_NAME` | 共有ファイルの名前 | `sharedFolder.json` |
| `BACKUP_FOLDER_NAME` | バックアップのフォルダ名 | `バックアップ` |

> アプリの共有ファイルの名前を変えたときは、`DATA_FILE_NAME` も同じに直してください。

## 9. うまくいかないとき

失敗すると、ntfy に理由が届きます。主なものは次のとおりです。

| 出るメッセージ | 原因 | 直し方 |
|---|---|---|
| Google の許可が切れています（invalid_grant） | OAuth が「テスト」のまま7日たった／許可を取り消した | 手順1で「本番環境」にして、手順2でリフレッシュトークンを取り直し、`GOOGLE_REFRESH_TOKEN` を登録し直す |
| ドライブに「sharedFolder.json」が見つかりません | アプリでドライブに接続していない／クライアントIDがアプリと違う／ファイル名が違う | アプリでドライブに接続できているか確認。手順2で**アプリと同じ**クライアントIDを使ったか確認。`DATA_FILE_NAME` を確認 |
| 共有ファイルのパスワードが変わっています | 共有ファイルのパスワードを変えた | 手順4で鍵を表示し直し、`DATA_KEY` を登録し直す |
| 共有ファイルは暗号化されています…DATA_KEY が未登録 | `DATA_KEY` を登録していない | 手順4→5 |
| 秘密情報 ◯◯ が登録されていません | 登録漏れ | 手順5をやり直す |
| Google Drive API が有効になっていません | Drive API が無効 | Google Cloud の「APIとサービス」→「ライブラリ」→ Google Drive API を「有効にする」 |
| 共有ファイルが空でした／読めませんでした | ドライブの同期の途中 | 自動でやり直します（数分後に3回まで）。続くときは、アプリで共有ファイルの状態を確認 |
| 前回までのバックアップがそろっていなかったので、フルを取り直しました | 増分が消えた・順番が合わない（注意の通知） | 自動で直っています。何もしなくて大丈夫です |

### 通知が来ないとき
- ntfy アプリで、**同じトピック名**を購読しているか確認します。
- `NTFY_TOPIC` を登録していないと、通知は送られず、ログだけが残ります（手順5）。

### ログを見たいとき
Cloudflare のダッシュボード → Workers & Pages → `tanbo-backup` → 「Observability（ログ）」で、実行ごとのログが見られます。

### もうバックアップを止めたいとき
`npx wrangler delete` で Worker を削除できます（ドライブのバックアップは消えません）。

## 10. 知っておいてほしいこと

- **データが大きいと、Cloudflare の無料枠（1回の処理に使えるCPU時間 10ミリ秒）に収まらないことがあります。**
  目安：データ（アプリの「JSONで保存」で出るファイル）が **約100KBまでなら大丈夫**です。もっと大きいときは、通知で知らせます。
  その場合は、有料プラン（月5ドル）にするか、私に最適化を頼んでください。
- バックアップのフォルダは、**Worker 自身が「マイドライブ」の直下に作ります**（Google の権限の仕組みで、アプリや Worker が見えるのは、自分で作ったファイルだけだからです）。
  フォルダの中のファイルを**手で移動・改名・削除しない**でください（鎖が切れて、フルを取り直すことになります）。
- 6か月以上バックアップが動かないと、Google の許可が切れます（毎日動いていれば問題ありません）。
- 古いバックアップは「ゴミ箱」に移るだけなので、30日間は戻せます。
- 復元のしかたは、**`復元手順書.md`** を見てください。
